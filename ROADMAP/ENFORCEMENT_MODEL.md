## 1. The Enforcement Model

### 1.1 What Sigil is (one paragraph)

Sigil is a **non-custodial, oracle-free, protocol-agnostic Solana agent-vault guardrail**. The agent key is the **sole runtime signer**; the vault owner holds all configuration authority and never co-signs execution. Spending is gated by an **atomic instruction sandwich**:

```
Transaction = [ validate_and_authorize , <untrusted DeFi instruction(s)> , finalize_session ]
```

`validate_and_authorize` snapshots the vault's stablecoin balance, runs pre-conditions, collects fees, and issues exactly **one scoped SPL `Approve` to the agent key** (`validate_and_authorize.rs:1059-1070`). `finalize_session` **re-reads the raw post-CPI token-account bytes** (Anchor's `Account` cache is stale after a CPI), measures the **actual** stablecoin delta, enforces caps on that measured delta, and **revokes the delegation in the same transaction** (`finalize_session.rs:198-209`).

### 1.2 The binding moat (what makes Sigil strictly stronger than Lighthouse)

Two structural facts, both verified, make the guard **non-omittable**:

1. **Forward-scan requirement.** `validate_and_authorize` introspects the instructions sysvar of the *current transaction* and refuses authorization unless a matching `finalize_session` is present downstream — `require!(found_finalize, SigilError::MissingFinalizeInstruction)` (err 6070, `validate_and_authorize.rs:908`).
2. **Same-tx delegation lifetime.** The `SessionAuthority` PDA is created with `init` (not `init_if_needed`) and closed at finalize; the `Approve` is paired with a `token::revoke` in the same atomic transaction. Delegation lifetime == transaction lifetime — a structural property, not a config knob.

A compromised transaction *builder* cannot simply omit the assertion (Lighthouse's advisory weakness): omitting `finalize_session` reverts `validate_and_authorize`, and with it the entire bundle. **This is Sigil's differentiator and must be protected against regression at all costs.**

## 2. The Decidability Boundary (First-Class Invariant)

This boundary is a **load-bearing, CONFIRMED, first-principles constraint** on what Sigil's architecture can *ever* prove. It is normative: **no future feature, claim, or marketing line may assert a capability on the "CANNOT prove" side of this line.** It is the single most important guardrail against scope-creep that would re-import the (correctly killed) instruction-parsing engine.

### 2.1 What Sigil CAN prove (enforceable)

- **CONSERVATION** — the *net quantity* of an identity-pinned token that entered or left specific, pinned accounts within the atomic transaction window. (This is the only fully-decidable safety claim Sigil makes.)
- **DESTINATION** — *where* value went, by reading the on-chain `owner` byte of each writable token account the SVM actually touches (recipient-owner allowlist) — **once the dead-on-seal plumbing is fixed (F1)**.

### 2.2 What Sigil CANNOT prove (forbidden to claim)

- **VALUATION** — the USD/market value of any volatile or *held* asset. There is no oracle. The numéraire is an *implicit 1.0* on USDC/USDT.
- **VERB** — whether an instruction is a swap vs a transfer vs a deposit. A −$500 swap and a −$500 transfer are **byte-identical at the endpoints `finalize` reads.** Verb is undecidable from vault deltas.
- **PATH** — intra-transaction routing. A drain-then-restore that nets to the same endpoints is invisible; only the net endpoint delta is observable.

### 2.3 STOCK vs FLOW

Sigil protects **FLOW** — value moving *through* the vault within the atomic window. It does **not** protect **held volatile STOCK** *between* sessions (a token sitting in the vault that drops 50% in price is outside Sigil's observable window, and valuation is undecidable regardless).

### 2.4 Normative consequences (binding rules)

1. **No verb-recognition feature.** Any proposal to "allow swaps / block transfers," "only permit lending," or otherwise classify instruction *intent* is **forbidden** — it is undecidable from deltas and re-imports the agnostic-violating opcode-as-semantics engine. The destination model expresses **WHERE + MAGNITUDE only**, never VERB.
2. **No volatile valuation feature.** Any proposal to bound spend by USD value of a non-stablecoin asset, or to "value the portfolio" on-chain, is **forbidden** without an explicitly-disclosed, owner-opted-in oracle (which is itself out of the default architecture; see §3 F2 and §6 Q3).
3. **No path/intent inference.** Any claim of "we detect drains" or "we see what the swap does" is forbidden; Sigil sees endpoints, not paths.
4. The opcode blocklist (G11) survives **only** as a *fixed-identifier* refusal of known-destructive primitives (same family as program-ID allowlisting), never as a semantic classifier. "No parsing for protocol SEMANTICS / value / verb / path" is **absolute**.

## 4. The Enforcement Stack (layers, in defense-in-depth order)

1. **Pre-execution authorization** (`validate_and_authorize`): identity/auth checks, program-ID allowlist, intent-digest scalar binding (G7), DeFi-ix count gate (G8), destination completeness (G5, to be fixed), fixed-identifier opcode refusal (G11), fee collection, scoped Approve.
2. **The DeFi instruction(s)** — untrusted, agnostic, taken verbatim from any source.
3. **Post-execution measurement** (`finalize_session`): raw post-CPI byte re-read, measured-delta cap checks (G3), floor check (G4), per-recipient cap (G6), output/input ATA identity pins (G9, to be added), unconditional revoke (G2).
4. **Intake gating** (`deposit_funds`): Token-2022 extension allowlist (G10) — the structurally-correct value-entry control; must be extended to the finalize chokepoint (§6 Q4).
5. **Configuration governance** (timelocks): `queue_*` → `apply_*` with 48h `DEFAULT_MIN_DELAY` for agent grants, owner-selectable timelock (floor `MIN_TIMELOCK_DURATION = 1800s`) for policy mutations; one-way cosign ratchet; owner-as-multisig recommended.
6. **Formal verification** (Certora cvlr): currently proves only tautologies — must be repointed at the conservation core (§6 Q9).
7. **Off-chain advisory** (SDK): simulation, fair-price estimation, depeg gate, monitor/auto-revoke. **Advisory only** — omittable by the exact compromised-builder threat the moat defeats; never advertised as a guarantee.

## 5. Claim Honesty — What Sigil May vs May Not Advertise

This section is normative for SDK comments, `docs/`, the dashboard, and the Blast Radius widget. **The advertised property must EXACTLY equal the on-chain-verifiable property.**

### 5.1 MAY honestly advertise (today, with the fixes in §7 shipped where noted)

- **"Your agent's spending authority exists only for the atomic window of each transaction and is provably revoked before that transaction ends — enforced on-chain, not by a dashboard."** (G1/G2, LIVE.) The strongest true line, and the differentiator vs Turnkey/Privy/Phantom (off-chain) and appended-assert tools.
- **"A guardrail your agent cannot skip"** — non-omittable post-condition; strictly stronger than advisory asserts (Lighthouse). (G1, LIVE.)
- **"Caps bound the stablecoin token *quantity* that can leave the vault within each transaction's atomic flow window."** Say **flow**, not holdings (decidability boundary).
- **USD-style caps without a price oracle** — but only with the re-denomination below. AHEAD of Squads/ERC-7715 (per-mint-only).
- **Non-custodial: no founder, protocol, or third party can touch a vault.** (F5, verified.)
- **"Spend-accounting is formally verified against under-counting and overflow"** — ONLY after F7 lands (today it is false; see §6 Q9). Never "Sigil is formally verified."

### 5.2 MUST NOT advertise (forbidden until fixed, or forbidden permanently)

- **A literal "≤ $N USD" guarantee.** FORBIDDEN — the numéraire is an implicit 1.0. **Required re-denomination:** "**≤ N stablecoin-token units, enforced on-chain non-omittably**, with an explicit worst-case-depeg caveat: a cap of N tokens permits ~$N×peg of value during a depeg (USDC hit $0.87 in the 2023 SVB event ⇒ a $500 cap permitted ~$575 of real value, ~15% silent under-protection)." The Blast Radius widget's "MAX YOU CAN LOSE TODAY: $X" must become a token figure or carry an explicit "at $1.00 peg" caveat.
- **"Destination allowlist" / "per-recipient caps" / "post-execution assertions" as ENFORCED** — FORBIDDEN until F1 lands; they are **dead on the `seal()` path** today. Flag as NOT-FUNCTIONAL-ON-SEAL in the interim.
- **"Protects your holdings"** or any STOCK claim — FORBIDDEN. Sigil protects FLOW, not held volatile value (decidability boundary).
- **"Allow swaps / block transfers" or any VERB capability** — FORBIDDEN permanently (undecidable, §2).
- **"Agnostic / no instruction parsing"** while `validate_and_authorize.rs:766` matches `ix.data[0]` — FORBIDDEN as worded. Honest dual line: **"reject-by-default extension *intake* gating is the guarantee; opcode blocking is belt-and-suspenders."**
- **"Fair price" / "no bad trades" / "safe"** — FORBIDDEN as an on-chain guarantee. A min-out floor *bounds* loss; it does not *prove* a fair price. Honest line: **"bounded conservation within the atomic window,"** never "safe." Fair-price protection is off-chain SDK simulation only.
- **"A leaked owner key can never drain"** — FORBIDDEN. Under *total* owner-key takeover, the attacker waits out the 48h window. Honest line: **"a leaked owner key cannot, by itself, *instantly* seat a fund-moving operator on a cosign-enabled vault"** — and only after F-Q6 closes the non-cosign `register_agent` OPERATOR path (§6 Q6).
- **"Persistent agent = standing on-chain authority"** — FORBIDDEN. "Persistent agent" = standing *identity* (agent roster) + standing *policy*, NOT standing custody.

### Q1 — Destination binding → **Option (c) BOTH, weight ON-CHAIN, split into two non-omittable invariants** (founder ratification needed)
**Decision.** (1) PRIMARY — a **destination-completeness invariant** in `validate`: every writable, non-vault token meta (owner ∈ {SPL-Token, Token-2022}) read from the instructions sysvar MUST be present in `remaining_accounts` and pass the allowlist; flip `destination_check.rs:150` from `None => continue` (fail-open) to a fail-**closed** reject. `seal.ts` must populate `validate`'s `remaining_accounts` with exactly those writable token accounts (the *satisfier*, not the enforcer). Apply the allowlist to the measured net stablecoin **sink**; treat transient route hops as resolve-required-but-not-allowlisted; add ATA-pubkey identity pinning between the validate snapshot and the finalize read. (2) SECONDARY (defense-in-depth) — promote the existing TS `computeSealInputDigest` (full programAddress + metas + roles + data) on-chain, replacing the 5-scalar `ScalarIntentInput`, so the executed bundle is byte-identical to the previewed one. (3) BLOCKING CO-REQUISITE in the same change set — close the free-SPL-delegation window (Q2). (4) RATIFIED — the model is **WHERE + MAGNITUDE only**; VERB-blocking is struck.
**Code confirmation (this audit).** `destination_check.rs:150` is `None => continue` (CONFIRMED fail-open). `seal.ts` never attaches `remainingAccounts` to `validateIx` (CONFIRMED — only mention at `seal.ts:833` is the removal comment; `composer.ts:80-82` passes the ix through unchanged) ⇒ **`enforce_destination_allowlist` is dead on `seal()`**. The scalar digest binds 5 fields only (`intent_digest.rs:104-140`, CONFIRMED). `validate` *does* read each meta's `is_writable` from the sysvar and each ATA's `owner` from real bytes (`destination_check.rs:130-169`, CONFIRMED) — so the destination set is derivable from runtime truth; only mandatory coverage is missing.
`Decision drivers:` tier-1 (output-reroute loss-of-funds) over DX/CU. (a)-on-chain wins as PRIMARY because it derives the destination set from a TRUSTED source (the sysvar + chain bytes the SVM executes), not attacker assertions; (b) is the smallest-trusted-surface integrity check (one hash-equality, binding ≠ parsing) but **cannot be primary** because the agent-ATA→vault-ATA rewrite makes a digest either stale or attacker-recomputable, and a digest proves "matches preview" not "destination allowlisted." REJECTED (a)-alone (reroute via meta-swap survives), (b)-alone (binds executed==approved but a hostile-yet-approved destination sails through), VERB-parsing (undecidable). Effort NON-WEIGHTING (Rule B, custody-adjacent). *Architect's accepted residual:* (b) is defense-in-depth, never primary; only (a)-on-chain + the Q2 fix fire against an SDK-controlling attacker. *CU caution:* resolving owner+mint for ~22-25 metas on a Jupiter route pressures the 1.4M-CU + tx-size budget and `MAX_DESTINATION_CHECK_METAS_PER_IX=16` hard-rejects large routes — retained as a required pre-merge CU profile and an *accepted* liveness limit (reject > silent-skip), not a reason to weaken.

### Q3 — Depeg / oracle → **Stay strictly oracle-free; three-part oracle-free remediation** (founder ratification needed for the claim re-denomination only)
**Decision.** Reject any price oracle on the stables (Option B) outright. (1) MANDATORY, ship-first: re-denominate every "≤ $N USD" claim to "≤ N stablecoin-token units + explicit depeg caveat" (SDK, docs, dashboard, Blast Radius). (2) Add an owner-only, **default-OFF**, monotonic `numeraire_haircut_bps` that can ONLY tighten the cap (`effective_cap = cap * (10000 − haircut_bps)/10000`). (3) Keep the manual freeze/kill-switch as the trustworthy depeg halt, surfaced in the dashboard + monitor alerts. Defer any *automatic* on-chain depeg breaker (the only oracle-free source, a USDC/USDT cross-rate, is infeasible because `is_stablecoin_mint` treats USDC/USDT as fungible 1:1 with no per-mint price).
**Code confirmation.** `finalize` measures a raw token delta with no price term (CONFIRMED, `finalize.rs:304-425`); `is_stablecoin_mint` at `state/mod.rs:540-542` is `mint == USDC || mint == USDT` with an explicit "MUST NOT widen" warning at `:551-555` (CONFIRMED). `freeze_vault` is `has_one = owner` and revokes delegations (CONFIRMED per F5).

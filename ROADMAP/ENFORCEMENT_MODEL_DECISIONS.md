## Q1-destination-binding  [HIGH · FOUNDER-RATIFY]

**Decision:** Option (c) BOTH — but with the load-bearing weight ON-CHAIN, and split into two non-omittable invariants enforced from sysvar-truth, not SDK promises. Apply the allowlist to the measured net stablecoin SINK, treat transient route hops as resolve-required-but-not-allowlisted, and add ATA-pubkey identity pinning between the validate snapshot and the finalize read. (2) SECONDARY (defense-in-depth, foundation-compatible): promote the existing TS computeSealInputDigest (full programAddress+metas+roles+data) into the on-chain verifier, replacing the 5-scalar ScalarIntentInput, so the executed bundle is byte-identical to the previewed/authorized one. (3) BLOCKING CO-REQUISITE shipped in the SAME change set: close the free-SPL-delegation window — refuse to arm the Approve when defi_ix_count == 0 under is_spending (and/or bind the Approve delegate-amount to the destination-checked outflow). (4) RATIFIED: the destination model constrains WHERE value went (recipient-owner allowlist, read from on-chain ATA owner bytes) + MAGNITUDE (cap on measured stablecoin delta) ONLY; it can NEVER express VERB ("allow swaps / block transfers"). Strike VERB-blocking as a stated capability and keep the opcode blocklist killed (demoted to account-relative intake gating).

**Drivers:** Security tier-1 (loss-of-funds via output reroute) ranks above DX and CU/byte cost; the deciding correctness property is NON-OMITTABILITY against an agent that controls the SDK. (a)-on-chain wins as PRIMARY because validate already reads every meta + its is_writable flag from the instructions sysvar (a TRUSTED source, load_instruction_at_checked at :398/:830/:888) and reads each recipient ATA's owner from real chain bytes — so it derives the destination set from runtime truth the SVM executes, not from anything the attacker asserts; the only missing piece is making coverage MANDATORY (reject on unresolvable writable token meta) instead of `None => continue` which silently rewards omission (verified dead on seal(): seal.ts:836 appends nothing, composer.ts:80 passes it unchanged, so destination_check.rs:150 skips every meta — CI is green only because tests hit agent_transfer, not seal()). REJECTED VERB-parsing: undecidable from vault deltas (a -$500 swap and a -$500 transfer are byte-identical at the endpoints finalize reads) and re-imports the agnostic-violating opcode blocklist. ## Q3-depeg-oracle  [HIGH · FOUNDER-RATIFY]

**Decision:** Keep Sigil STRICTLY ORACLE-FREE. Do NOT add any price oracle (Pyth/Switchboard/etc.) on the stables — reject Option B outright. Execute a three-part oracle-free remediation: (1) MANDATORY, ship-first claim-language correction — re-denominate the guarantee everywhere (SDK, docs, dashboard, Blast Radius widget) from "≤ $N USD" to "≤ N stablecoin-token units, enforced on-chain non-omittably, with an explicit documented worst-case depeg caveat (a $N cap permits ~N tokens, ~$N*peg of value during a depeg)"; (2) add an owner-only, DEFAULT-OFF, monotonic numeraire_haircut_bps that can ONLY tighten the effective cap (effective_cap = cap * (10000 - haircut_bps)/10000), giving a risk-averse owner a self-declared depeg margin with zero external input; (3) keep the existing manual freeze/kill-switch (confirmed in freeze_vault.rs — revokes active SPL delegations atomically) as the trustworthy depeg halt, surfaced in the dashboard + off-chain monitor alerts. Defer any automatic on-chain depeg breaker as NOT-NOW: the only oracle-free automatic source (a USDC/USDT par-deviation cross-rate) is INFEASIBLE without re-architecting, because the code treats USDC and USDT as fungible 1:1 (is_stablecoin_mint, state/mod.rs:540-542) and measures a single stablecoin_delta with no per-mint price.

**Drivers:** Security lexicographic order decides it: a price oracle in the validate hot-path is a tier-1/tier-2 risk (oracle staleness/halt = brick of owner funds = permanent loss of control, ranked EQUAL to theft; oracle manipulation = DeFi's #1 loss-of-funds class, cf. Mango ~$114M) introduced to patch a tier-3 correctness gap (caps loose by ~15% only during a rare transient depeg, fully owner-recoverable). Higher tier wins outright, no balancing. The chosen oracle-free path wins on smallest-trusted-surface — it adds ZERO attacker-feedable inputs and ZERO new external liveness dependency to a system whose entire moat (verified: finalize_session.rs:415-423 measures raw token delta vs *_usd with no price term; oracles "removed by design" per agent_spend_overlay.rs:66) is having nothing for a compromised builder to feed. REJECTED — Option B (price oracle): loses because it converts a bounded ~15% quantified gap into an unbounded, attacker-triggerable freeze-or-stale-price surface and adds a trusted third party over a non-custodial vault, violating TWO locked foundations (oracle-free + non-custodial) to fix an accounting/marketing defect; also irreversible (IDL/account-model/TCB change) where the chosen path is reversible policy. REJECTED — Guardian's default-ON oracle-free par-deviation breaker: loses on FEASIBILITY (USDC/USDT are fungible 1:1 in code — no per-mint price exists to compare without re-architecting the stablecoin model) and on SECURITY (a default-ON breaker reading a thin/illiquid stable pool is an attacker-triggerable mass-freeze = tier-2 brick; a one-block wick bricks every honest vault exiting into stables exactly when exit matters most). REJECTED — words-only / accept-15% with no code knob: loses because it leaves the silent under-protection live with zero owner remedy; the monotonic haircut closes the silence at zero trust cost.

**Dissents:** Architect + Founder: an OPT-IN, default-OFF, owner-armed on-chain depeg control may eventually be warranted (peg-band/staleness assert, or a future execution-revealed stable-stable reference leg) for owners who reject the off-chain-monitor trust assumption. This is COMPATIBLE with the lock (default path stays oracle-free; oracle becomes a deliberate owner-scoped opt-in, never a foundation-wide mandate) but is deferred as a separate scoped design decision — its source/staleness-window/fail-open-vs-fail-closed must be specified, and fail-closed on a halted source is itself a tier-2 brick risk. Architect: an off-chain SDK depeg gate is cheap/upgradeable/fail-safe but is OMITTABLE by the exact compromised-builder threat the binding moat exists to defeat — so it is advisory-only, never a substitute for on-chain enforcement, and must not be advertised as a guarantee. | Guardian (conceded by Guardian itself): if no manipulation-resistant oracle-free source exists for a vault's stables, the honest fallback is claim-language + accept-the-gap, NOT a price oracle — the tier-1 liveness/trust cost of the oracle still outranks the tier-3 cost of ~15% under-protection. This dissent's own escape clause confirms the lock. | Offensive engineer (implementation guard, MUST encode): numeraire_haircut_bps must be Certora-verified monotonic-DECREASING in haircut_bps and applied as a cap TIGHTENING, never as a multiplier on measured delta — a sign error would LOOSEN the cap into a drain vector.

**Impl:** Founder ratifies ONE irreversible posture sentence only — the public-claim re-denomination from "USD guarantee" to "stablecoin-UNIT cap with explicit depeg caveat" (one-way framing decision; the founder owns honest-advertising/liability). The oracle-NO and the haircut design are decided autonomously on security-priority grounds and do not need ratification.
